**Fixed the `GET /orders/my` bug** found during the URL-restructuring verification. Root cause:
`getUserOrders`/`getAllOrders` in `order.service.ts` destructured only `{ skip }` from
`paginationParams(page, limit)`, discarding its sanitized `limit`, then passed the raw
(potentially-`NaN`, when the client sends no query params) `limit` straight to Prisma's `take` —
which Prisma rejects. Fixed both call sites (the identical pattern existed in the admin
`getAllOrders` too, fixed proactively). Verified live: booted the backend, minted a real JWT for
the seeded admin via the actual `signAccessToken` secret, called `GET /orders/my` with no query
params (the exact failure case) and got `200`, plus `?page=2&limit=5` and the admin `GET /orders` —
all clean. `wood-vintage/backend` commit `68db808`, pushed to both `origin` and `woodvintage`.

## Skills / knowledge gained
- Read the actual existing code before trusting a spec's own claims about what does/doesn't exist
  — the URL-restructuring spec's first draft was wrong about middleware, caught by verification
  before implementation started, not after.
- `rm -rf .next` between `npm run build` and `npm run dev` in the same session (logged to
  `skills/SKILLS.md`) — a real gotcha hit while verifying the Countries admin UI.
- Hiding a UI toggle is not the same as neutralizing its default. Disabling the gender-toggle admin
  setting alone would have silently scoped the whole catalogue to `genderSlice`'s old `'WOMEN'`
  default with no toggle left for anyone to notice — the fix had to change the *default value*
  (`'ALL'`), not just hide the control. Worth remembering for any future "remove/hide this filter"
  request: check what the underlying state defaults to, not just whether the control is visible.
